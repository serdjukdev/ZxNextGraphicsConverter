# Changelog

## Unreleased

- Added: object ANIMATIONS, exported as one project-wide `object_anims.asm`. An object now holds named animations, each a list of frames, and a frame is one row layout plus how long it is held. Each animation becomes one self-contained table for your own drawing routine: `db <frames>`, then one `dw` per frame; each frame is `db duration, sprites, X mirror correction, Y mirror correction`, then the ANCHOR sprite as `db palette, pattern` with no offset at all (the object's own X/Y on screen IS the anchor's position), then 4 bytes per following sprite, `db dx, dy, palette, pattern`, with dx/dy SIGNED from the anchor's top-left pixel. The anchor is the frame's first sprite in reading order. The palette byte is each sprite's own 4bpp slot already shifted into bits 7:4, so it ORs straight into a sprite attribute byte and one frame may mix palette slots freely. The two mirror corrections are dx_min + dx_max and dy_min + dy_max of the frame, because hardware mirroring negates an offset without compensating for the group's width. Every animation also gets an `obj_<object>_<animation>: equ <table>` alias, so your code names an animation instead of carrying an address; there is deliberately no table of animation addresses above them. A still object is a one-frame animation and exports exactly the same shape, so nothing needs a special case. The only number typed by hand is a frame's duration (which is the animation's speed, 0 meaning it changes every game frame); everything else is measured from the layout.

- Added: an animation strip and a frame strip in the Object Editor, above the row editor. "Add..." creates another animation of the selected object (it asks for a name); Rename and Delete are on the animation's own right-click menu, and dragging reorders them, which matters because the FIRST animation's first frame is the picture a map draws. "Add frame" adds a frame right after the selected one, copying its layout and its duration, since consecutive frames usually differ by a detail. Each frame shows its own thumbnail with its number, right-click one to delete it, and dragging reorders them: frame order IS play order. The "hold" box is the selected frame's duration in game frames. Clicking a frame loads it into the row editor below, so rows, cells and offsets always edit the selected frame. Flipping through the frames is the preview. A project from an earlier build opens with its existing layout as the single frame of one animation named "main", so nothing has to be rebuilt.

- Fixed: a project saved by the first build that had objects could not be opened at all if any object had an empty cell. That shape wrote an empty cell as a bare JSON `null`, and System.Text.Json never hands a `null` to a reference type's converter, so the converter's own "empty cell" branch was dead code and the null reached the reader, which threw. The reader now handles nulls and treats a missing cell as an empty one however it got into the file.

- Changed: object types and their subtypes moved out of the Map Editor's "Manage Types..." dialog, which is gone, and into the Object Editor as a second tab beside Objects. A type is project-wide exported data, not map data (it is the object record's type byte, the `obj_<name>` numbers, each map's per-type counts and the init order those numbers give), and the Object Editor is where a type is already picked for an object, so the separate trip was pointless. The Types tab follows the same shape as the rest: each type is listed WITH the export number it currently has, one "Add..." button asks for a name, Rename and Delete sit on the type's own right-click menu, and dragging a type to another position changes its exported number (and with it the init order of its objects) with a green line showing where it will land. Below the list are that type's width and height defaults, which a placement with this type but no object of its own still exports, and its subtype list with the same Add-plus-right-click shape and the bit picker. Deleting a type is still refused while anything uses it, and now also clears it from any object that handed it to its placements.

- Added: objects can now be PLACED on a map. The Map Editor's Sprite-layer palette has two tabs above it, "objects" and "root"; objects is the default whenever the project has any. An object shows as its whole picture in the palette, and clicking the map drops it exactly like a sprite: freely, or snapped to the 8x8 tile grid while Shift is held, with the green snap preview now sized to the object instead of a fixed 16x16. The map draws the whole object, every sprite and every row offset included, so a platform looks like a platform instead of one marker sprite standing in for it. A placed object brings its object's type and user byte with it, and writes that object's measured width and height into its extended bytes. Everything that works on a placement now works on its real area rather than on the 16x16 of its base sprite: the click that selects or erases it, the Alt-drag marquee, the red erase preview and the selection outline. The "root" tab is the palette exactly as it was, for placing a single sprite.

- Added: an Object Editor (Tools menu), where an object is a named group of sprites: a 5-wide platform, a character of one sprite over two. It is built from ROWS, not a rectangle, because real sprite compositions are not rectangular: each row has its own number of cells (its own +/- buttons) and its own pixel offset, so a character's two lower sprites can sit centred under its head at dx -8 with no empty filler cell anywhere. The same sprite can fill as many cells as you like, which is how a platform repeats its centre piece. The sprite palette has a strip of folder buttons above it, so sub-folder sprites can be used too, and lists each folder's sprites in their real project order rather than alphabetically. An object also carries the type and the whole user byte (the number, its 8 bits, and the type's named subtypes, all editable in place) that every placement made from it starts with, and its size in pixels, either measured from the picture or typed by hand for the cases where the exported size is a hitbox rather than the picture's extent. Objects are optional: a project with none behaves exactly as before.

- Added: what a placement made from a named object exports is the object's own size rather than a number typed on its type: its measured extent, or the size pinned by hand in the Object Editor when the exported size is a hitbox rather than the picture's extent (see "Extended object bytes" below). The order of precedence is the placement's own pinned values first, then its object, then its type, then the sprite's own size. The layout itself reaches the export only as the object's animation tables (see above), never as the placement's record: your own code decides which sprites a placed object really uses, from its type and user byte.

- Fixed: a project saved by a build in the middle of this feature's development could not be opened at all: a changed property type in the manifest threw during load, and the failure was only reported in the status line at the bottom of the window, so the app looked like it had opened an empty project. The manifest reader now accepts every shape an object definition's cells were ever saved in, and a failed open shows a dialog naming the file and the error, and says the file itself has not been changed.

- Added: named SUBTYPES for an object type, each owning one bit of a placed object's user byte. Add them in "Manage Types..." under the selected type (at most 8, one per bit): a new one takes the lowest free bit and can be moved to another afterwards, while a bit a sibling subtype already owns is refused, naming the owner. A subtype's name is unique across the whole project, because its exported label carries no type name: `subobj_<name>: equ <bit value>` in object_types.asm, the bit's VALUE (1, 2, 4, ...) rather than its index, so game code tests it with a plain AND. On the map, right-click an object for "Set User Byte" and the dialog now also lists that object's type's subtypes: picking one sets its bit and clears the OTHER subtype bits, since an object is one variant of its type and not a combination. Bits no subtype owns are never touched, so a type can carry a subtype and a hand-entered parameter in the same byte, and the number box and the eight bit buttons still set any combination they like. A type with no subtypes leaves the dialog exactly as it was. Deleting a subtype deliberately leaves every placed object's user byte alone: that byte is raw game data, and silently clearing a bit across every map would be the bigger surprise.

- Changed: a Sprite4Bpp sprite's and a Tile4Bpp tile's palette is now exported as an `equ` constant instead of a data byte, and already shifted into the high nibble the hardware reads it from: `s4_hero_pal: equ 32   ; slot 2` ORs straight into a sprite's attribute byte, `t4_grass_pal` likewise into a tilemap attribute byte. An `equ` costs no memory at all, so naming the palette a sprite needs in your own code is now free, where before every sprite and tile spent one real byte on a value a game that sets palettes by name never reads. Tile4Bpp also gained the tile NUMBER as its own constant, `t4_<name>: equ <n>`, which it never had; note that `t4_<name>` therefore means the tile number now, where it used to be the ADDRESS of that tile's palette byte. The same slots are still available as a real byte table for a runtime lookup (`s4_pal_table + spriteIndex`, `t4_pal_table + <tile number>`, and each sub-folder's own `s4_<subfolder>_pal_table`), pre-shifted the same way, written as one contiguous run at the end of the file; that table is the only part that costs bytes, so a new Settings checkbox "Export palette lookup tables" (on by default, so nothing silently disappears from an existing project's export) can drop it entirely.

- Added: two more bytes per exported map object, switched on by the new Settings checkbox "Extended object bytes": byte 8 is width in pixels, byte 9 is height in pixels. The bytes are ALWAYS written, inside an `IFDEF OBJ_EXT` block right after each object's own db line, and every map's objects file also gets a `<map>_objects_obj_size` constant that is 10 with the define on and 8 with it off, so game code steps through the table without hardcoding either number. The switch itself is a single `DEFINE OBJ_EXT` line in the project-wide object_types.asm, written active or commented out according to the checkbox: one line decides the record size for every map at once, it can be flipped by hand in the exported source without re-exporting, and more bytes can be appended later the same way. With the checkbox off the export assembles byte for byte what it always did. Values come from the object's TYPE (width and height in pixels, defaulting to 16x16, set on the Object Editor's Types tab), a named object's own measured or hand-pinned size beats that, and any single placement can pin its own instead: right-click it on the map for "Object Data...", where each of the two either follows the type or is fixed on that object. Right-clicking an active selection applies the values to every selected object at once, as one undo step. An object with no type at all exports its sprite's own pixel size. object_types.asm also gains each type's own `obj_<name>_w` / `_h` constants inside the same IFDEF block. There is deliberately no palette byte in the record: a sprite's palette travels with the sprite itself, in the object's animation table.

- Added: "Replace image..." now works on a whole metatile too, from its right-click menu in the Metatile Editor's gallery: the region you pick, the size of the metatile's own footprint, is cut into its 8x8 cells and each piece replaces that cell's TILE in place. The metatile keeps its name, its export index (the byte every map grid cell stores for it) and every placement on every map, and so does each tile it is built from. Before anything changes, a confirmation spells out the three things that are not obvious: a tile shared by two cells cannot show two different pictures, so the first cell replaces the shared tile and each later one gets a new tile appended (which moves no existing export index); a cell currently showing the project's blank tile gets its own new tile instead of overwriting the blank that every empty map cell points at, unless its new piece is fully transparent too, in which case the cell is left alone; and a cell's mirror/rotate flags are cleared, since the new piece is written the right way round rather than flipped by hardware. The same confirmation names every OTHER metatile built from the tiles being replaced, which change along with them. Colours are re-converted from scratch, so a 4bpp tile can land in a different palette slot than before, and a tile whose colours do not fit goes through the usual reduce-and-retry dialog while the rest of the cells still go through. Not undoable.

- Added: right-click a tile, sprite or Layer2 image for "Replace image...": give it a new picture without deleting it and importing a new one. The asset stays the same asset, so its name, its export index (the number your own code has hardcoded), its lock, its folder position, and everything built on it (metatile cells, map placements, animation targets) are all untouched; only the pixels and its palette colours change. The new picture is taken from a source image in the project, picked from a list in the dialog, with "Browse..." adding a file from disk to that list first, so the tile keeps a live source link and can still be re-quantized or re-dithered afterwards. The replaced tile also stops referencing its old source image, so once nothing else is made from that image, deleting it from the Source Images panel is a plain one-question delete. Aiming at one cell of a big sheet has three separate controls that do not interfere: a left click jumps to a whole cell, the arrow keys move the selection one pixel at a time (whatever has the keyboard focus), and an "Image offset" pair says where the cell grid starts in that image, for a sheet with a border or one whose cells do not begin on a multiple of the tile size, applied as you type with no Enter needed. The window is resizable and opens showing the whole image; the mouse wheel zooms around the pixel under the cursor through whole-number steps (it stops at either end instead of wrapping round), and holding the middle mouse button drags the picture. For a Layer2 image there is no cell grid: the click positions the canvas freely and a source smaller than the canvas is padded with transparent, exactly as on import. A replacement that does not fit the palette goes through the usual reduce-colours-and-retry dialog. Replacing a whole metatile's picture at once is not part of this yet.

- Changed: deleting metatiles now lists their names in the confirmation instead of only counting them ("Delete 3 unused metatile(s)?"), the way the tile/sprite "Delete unused..." sweep always has. Applies both to "Delete unused metatiles" and to deleting a hand-picked multi-selection in the Metatile Editor's gallery, which is irreversible and was equally unreadable before.

- Fixed: re-quantizing a sprite that was already placed on a map, or changing its folder's dither mode, silently broke every placement of it: the replacement was a brand-new asset with a new id, so the map's placements kept pointing at an id that no longer existed. The Map Editor then drew nothing where that sprite stood and the export refused the whole project with "Map 'X' places a sprite that no longer exists". A re-quantized tile that was an animation frame bank's target tile lost its animation link the same way. Replacing an asset in place now reuses the replaced asset's own id, so placements, metatile cells and animation targets stay valid by construction rather than needing to be hunted down and repointed afterwards, and the repointing pass that does still run (for a failed re-import, whose cells fall back to the reserved blank tile, and for a regenerated blank) now covers all three kinds of reference instead of metatile cells alone. Existing projects already damaged by this need the affected sprites placed on the map again, since the dead id carries no information about what it used to be.

- Fixed: a map whose name contained a space, a dot or any other character an assembler label can't hold exported labels that sjasmplus refuses, for example `my level_tilemap_grid_width: equ 40`, so the whole export wouldn't assemble. Every map row's key (grid, metatiles, objects and info, for both layers) now goes through the same label sanitizer that object type names have used since v0.6.0: "my level" becomes `my_level_...`, "level.1" becomes `level_1_...`, and a name starting with a digit gets a leading underscore. The configurable export postfixes from Settings are sanitized the same way, since a space typed there broke labels identically. The output filenames follow the sanitized key too (`my_level_tilemap_grid.asm`). A name that was already label-safe is unchanged, so existing projects' labels and filenames stay exactly where they were.

- Added: the export now writes a tilemap tile animation's numbers as `tm_anim_<folder>_*` constants, at the end of that frame bank's own section of the Tile4Bpp address map: `first` (the first tile overwritten), `tiles` (per frame), `frames`, `frame_size`, `offset` (where frame 0 starts in the bank's binary) and `size`. A frame change is then source = `offset + frame * frame_size`, destination = the tilemap's tile-definitions base + `first * 32`, length `frame_size`, with nothing hardcoded: reorder or insert tiles and the next export just has different numbers. `seq` is 1 when the targets are consecutive, so one linear copy does a whole frame; if they are scattered it is 0, `first` is omitted entirely, and a `tm_anim_<folder>_targets: db ...` table lists the tile each position overwrites instead. Rather than emit numbers that would be quietly wrong on hardware, the export stops with a clear message when the bank holds a part-finished frame, when a target tile is gone, or when the bank got split across several binary files at the chosen chunk size (set that row to "whole file"). Frame timing is still entirely your own code's.
- Added: importing a tile into an animation frame bank now forces it into the palette slot of the tile that frame position overwrites, instead of letting the 4bpp bucketing algorithm pick a slot: substituting a tile's pixels never rewrites a map cell's attribute byte, so a frame in any other slot renders with the wrong colours on hardware, silently. The position comes from the folder's own tile order, which is the frame order, so slicing a whole animation in one go cycles through the target slots by itself, and re-quantizing one frame keeps the position it already had. Colours missing from that slot are added to its free entries only, never replacing what is already there, so every other tile in that slot keeps rendering exactly as before. If they don't fit, the import is refused with a message naming the slot, through the usual palette-overflow dialog where you can reduce colours and retry, which is the right remedy here (no other slot would do).

- Added: right-click a Tile4Bpp sub-folder for "Animation target..." and pick, as a picture, the metatile (one frame = all its tiles) or the single tile (one frame = 32 bytes) whose pixels this bank's frames overwrite at runtime. Everything else follows from that: tiles per frame, how many complete frames the folder holds, bytes per frame, and the palette slot each frame position must use. The dialog, and the status line after OK, names what would otherwise only show up as a broken animation on real hardware: a tile count that isn't a whole number of frames, a frame tile sitting in a different palette slot than its position's target, a target tile that no longer exists, and targets that aren't consecutive tile numbers (so one linear copy per frame cannot land on them). It also lists the other metatiles built from the same tiles, since substituting a pattern is global and animates them too, which is often exactly the point. The setting lives on the folder, is saved in the project, and survives tile reordering because it stores tile references rather than numbers. Frame timing and the copy itself stay entirely your own code's business.
- Added: Tile4Bpp now supports sub-folders, as animation frame banks for the hardware tilemap. A bank's tiles never take a placeable root tile index, so they don't eat the 256-tile tilemap budget (the Atlas Slicer's remaining-capacity preview counts root tiles only too), and they export to their own `.til` binary while the category still writes one `.asm` and one `.pal` as before. Inside a bank nothing is de-duplicated or dropped: a fully transparent piece becomes a real transparent tile and two identical pieces stay two tiles, because a frame is copied into tile pattern memory as one contiguous run of 32-byte tiles, so every position must physically exist (the slicer's "Skip duplicate cells" is forced off and greyed out when slicing into a bank, and the all-transparent tile is no longer folded into the category's reserved blank there). A bank's asm labels are `t4_<subfolder>_<name>: equ <index>`, a zero-byte bank index (byte offset = index * 32) instead of a palette byte: substituting a tile's pixels never rewrites a map cell's attribute byte, so the palette slot cannot change with the frame and the running code has no use for it. "Delete unused..." skips frame banks, which it would otherwise wipe entirely, since no map places a frame.

- Fixed: shrinking a map with "Resize..." left every object that stood in the cut-away area sitting outside the new bounds. Such an object was invisible in the Map Editor and impossible to select or delete there (the canvas is exactly the map's size), yet it was still written into the exported `<map>_objects.asm`, with coordinates outside the level. Only objects pushed to a negative coordinate (off the left/top edge) used to be dropped; the right/bottom edge now drops them the same way, so the Resize dialog's "Will drop N sprite(s)" count is what actually happens. An object merely overhanging the new edge, with its top-left corner still inside, is kept, since that is a position you can place by hand too. A Link pointing at a dropped object is cleared, and one Undo restores the whole resize, dropped objects included.
- Fixed: the same off-map objects could also be created by Alt-dragging a selection past the map's edge (or Alt+Shift+dragging a copy there) and by pasting a group of objects near an edge or onto a smaller map. Those now drop, exactly like grid cells moved off the map always have, and the status line reports how many.
- Fixed: a project already damaged by the resize bug above is repaired when you open it: every object outside its map's bounds is removed (links pointing at one cleared) and the "Project opened with notes" dialog says how many. Without this the stale objects would have kept exporting until the next resize of that map.

- Added: every map now exports its own geometry row, `<map>_info.asm`: one sjasmplus `MODULE <map name>` holding the whole map's measurements as short-named `equ` constants, plus `hdr:`, the same numbers again as real `dw`/`db` data for engine code that is handed a pointer to a map rather than assembled against one. Width and height come in all three units (`w_mt`/`w_t`/`w_px` for metatile cells, 8x8 tiles and pixels, same for `h_`), and so do all four sides as inclusive extreme coordinates (`left_`/`top_` are 0, `right_`/`bottom_` are the last valid coordinate, so a bounds test needs no -1). Alongside them: the metatile cell size with ready-made shift counts (`cell_t`, `cell_px`, `cell_tsh`, `cell_psh`, `tile_px`), the totals (`cells`, `tiles`), and each grid layer's own bytes per cell, row stride and total size (`tm_bpc`/`tm_row`/`tm_size` for the Tilemap layer, `l2_` for the 8bpp one; only a 1x1 map's Tilemap layer is 2 bytes/cell). The module is what keeps the names this short: `w_px` inside is `level1.w_px` outside, so every map's info file can be assembled together with no clash. The `hdr:` block lays its 16-bit fields out first and its byte fields after, each with its own label and a `; +offset` comment, closing with `hdr_len`; on an extreme map where a field would not fit a word it is dropped entirely with a comment saying which field overflowed, rather than writing one truncated value (the `equ` constants stay exact either way). The postfix is configurable in Settings like every other export postfix. The grid files keep their own `<map>_<layer>_grid_width`/`_height` constants and now just point at the info file.
- Added: right-click a metatile in the Metatile Editor's "Existing metatiles" gallery for "Rename... (F2)". Renaming was only possible by selecting the metatile, retyping its Name and clicking "Save Changes", which also needed every draft cell filled first; the new menu item (and F2 on the selected metatile) renames it directly and leaves whatever is in the draft alone. A name another metatile already uses is refused with a message in the dialog rather than auto-uniquified to `_2` the way Create/Save Changes does it, since an explicit rename should not quietly store a different name. On a 1x1 project the metatile is a wrapper around a single tile, so this renames that tile too and the Project Tree updates to match (the same "they are one unit" rule the 1x1 delete already follows). The reserved "Blank" metatile cannot be renamed.
- Added: Settings checkbox "Set ULA-over-tilemap bit (bit 0) on every exported Tilemap attribute byte" (off by default). Every 4bpp Tilemap tile's exported attribute byte (bits 7-4 palette, bit 3 Mirror X, bit 2 Mirror Y, bit 1 Rotate) has an unused bit 0 that real hardware (nextreg 0x6C) reads as a per-tile ULA-over-tilemap priority flag; off keeps writing 0 to every tile's bit 0 as before, on writes 1 to every tile's bit 0 instead, in both the GridSize=1 direct-cell export and every metatile cell. One project-wide export switch, not a per-tile editor control. The affected `_grid.asm`/`_metatiles.asm` header comments state which value was used.
- Added: a map's exported `<map>_objects.asm` now writes an address label, `<map>_objects_<type name>:`, right before the first object of each type in the file (objects are already grouped by type, see the per-type `_count` lines added earlier). A type with 0 objects placed on this particular map gets no block label, and untyped objects never get one either, since they aren't a real entry in "Manage Types...".
- Added: right-click now applies "Set Type" / "Set User Byte" to the WHOLE sprite selection at once, when one is active (Alt-drag a marquee first, then right-click anywhere on the canvas). Previously right-click only ever targeted whichever single object sat directly under the cursor, so tagging several objects the same type still meant clicking each one individually even with a selection made. The picked type/byte overwrites whatever each selected object already had, as one undo step; the "Link" menu item is hidden in this batch mode since linking is pairwise. The existing one-object-at-a-time "Set Type"/"Set User Byte" toolbar tools are unchanged for tagging objects that aren't selected.
- Added: a map's exported `<map>_objects.asm` now writes one `<map>_objects_<type name>_count: equ` constant per project-wide Object Type (from "Manage Types..."), in that list's order, right after the existing `<map>_objects_count`. A type that places 0 objects on this particular map still gets its own `_count: equ 0` line, so game code can always rely on every type's count constant existing regardless of which maps actually use it.
- Added: the Export dialog now shows a prominent red warning banner listing every placed object across every map that has no type assigned (e.g. "Level1: Enemy at (32, 64)"), so a forgotten "Set Type..." doesn't silently slip into an export. Non-blocking: Export stays enabled either way, an untyped object exports fine.
- Added: a "Show in Map Editor" flag for Sprite4Bpp/Sprite8Bpp sub-folder sprites, set per sprite from a checkbox next to the padlock or the right-click menu (tooltip explains it). Any number of sprites in one sub-folder can be flagged, for example several different enemies' idle frames sharing one 16KB pattern bank, each independently placeable on a map. Flagged sprites join root sprites in the Map Editor's sprite palette regardless of the broader "Allow sub-folder assets in map/metatile editor" setting; a placement's exported `spriteIndex` always resolves from that sprite's own local export index within its sub-folder, so toggling the flag later never changes already-exported map data. Purely a palette-curation flag, cosmetic only.
- Added: the Project Tree's status line now shows a Sprite4Bpp/Sprite8Bpp folder's bank usage (bytes used out of the 16KB shared sprite pattern memory pool) when that folder or an asset in it is selected.
- Added: object types in "Manage Types..." can now be reordered with Move Up/Down buttons. List order already set each type's export `equ` number in `object_types.asm`; it now also controls the init order of that type's objects within every map's exported `<map>_objects.asm`. Objects are grouped by their type's list position (untyped objects always last), with the relative order preserved within one type and among untyped objects. Useful when a type with many placed instances, e.g. a platform type, needs to initialize before other types on real hardware.
- Added: a "Templates" palette in the Map Editor, next to the existing Metatile palette (toggle between the two with the buttons above the list). Select a rectangle on a grid layer and click "Save as Template..." to name and store it: a reusable WxH block of graphics only, no map objects. Templates filter by Kind/GridSize exactly like the Metatile palette, so a Tilemap template never appears while the 8bpp layer is active and vice versa. Selecting a template arms a stamp tool: a translucent blue footprint follows the cursor over the canvas, and a click writes the whole block at that position in one undo step, silently clipped at the map's edges rather than refused. "Delete Template" removes the selected one (not undoable, same as deleting a map). Templates are stored project-wide and stay correct if a metatile they reference is later deleted or reordered elsewhere in the project.
- Added: in Atlas Slicer's "Slice into metatile blocks" mode, a block whose resolved tile composition (same tiles, same cell order) exactly matches a metatile already created earlier in the same slice now reuses that existing metatile instead of creating an identical duplicate. The default-selection/capacity preview (the "N metatiles will be made" count and the 255-per-Kind cap enforcement) accounts for this too, so a whole-block duplicate no longer costs a metatile slot there either.
- Added: the Source Images panel now accepts Ctrl+V to paste an image from the clipboard as a new source image (named `clipboard_<timestamp>`), alongside the existing Import/drag-and-drop. Reads the clipboard's "PNG" format, "Photoshop DIB Layer X", or CF_DIBV5 first (all of which can carry a real alpha channel), falling back to the plain bitmap otherwise. If no format in the clipboard actually carried transparency (a known limitation of some apps' copy, including some Photoshop versions, which paste an opaque 24bpp image with no alpha at all), a warning dialog says so and the image is pasted fully opaque; export/save it as a PNG file and import that instead if it needs transparency.
- Changed: a map's exported `_objects.asm` header comment now lists each of the 8 placement bytes on its own line (byte 0 spriteIndex, 1-2 X, 3-4 Y, 5 type, 6 connect, 7 userByte) instead of one dense paragraph.
- Added: hovering over a sprite in the Map Editor's sprite palette now shows a tooltip with the sprite name and how many objects of that type are currently placed on the active map (e.g. "Enemy (3 on map)"). The count updates after every placement, erase, paste, delete, copy, resize/trim, undo, and redo.
- Added: right-click "Lock all in folder" / "Unlock all in folder" on any category root or sub-folder, as a faster alternative to clicking each padlock one by one. Scope is always the folder's own direct assets (root-folder assets for a category root; the sub-folder's own assets otherwise). A status line confirms how many were changed.
- Added: Settings checkbox "Organise output into sub-folders matching the project tree" (off by default for compatibility). When on, the export directory gets a named sub-folder per asset category (e.g. `Sprite8Bpp/`, `Tile4Bpp/`) and a further sub-folder per user sub-folder inside it; shared category-wide `.asm`/`.pal` files go into the category root, per-subfolder binaries into their own sub-directory. Tilemap grid/metatile files go into `Tile4Bpp/`, 8bpp grid/metatile files into `Tile8Bpp/`. Objects and object types stay at the output root.

- Changed: a project now uses ONE metatile grid size (2x2/3x3/4x4) for everything: every metatile of either Kind and every map's grid layers. Chosen once, lazily, the first time it's actually needed (opening the Metatile Editor, or creating the first map) via a small one-time dialog; fixed for the rest of the project's life. The Metatile Editor no longer has a per-metatile size picker, and the New Map dialog no longer has a per-map one. Existing projects saved before this infer their locked size from whichever size their own metatiles/maps already use.
- Added: every tile/sprite row in the main project tree now shows a small thumbnail of its own actual pixels (native size, nearest-neighbor scaled), staying in sync on import/re-quantize/undo-restore and while live pixel-editing the currently selected one.
- Fixed: a drag-reordered tile/sprite tree reverted to its original (pre-reorder) visual order after saving and reloading the project: reordering only ever changed each asset's SortIndex, never `ProjectState.Assets`' own list order, and the tree was rebuilt from that raw list order on load instead of from SortIndex. The tree now always rebuilds in SortIndex order.
- Added: a thin blue line shows exactly where a dragged tile/sprite row will land while dragging, and the tree auto-scrolls while the mouse hovers near its top/bottom edge.
- Fixed: the project tree scrolled all the way back to the top on every single drag-reorder drop: the move was implemented as Remove+Insert, which tears down and regenerates the dragged row's visual container; switched to `ObservableCollection.Move`, which repositions the existing container instead.
- Added: drag a tile/sprite row onto another one in the project tree to reorder it (drop on the top/bottom half of the target row to land before/after it): reassigns real export indices to match, for the whole category (Tile4Bpp/Sprite4Bpp, which have no sub-folders) or the same sub-folder only (Tile8Bpp/Sprite8Bpp: a different folder there is a separate flat palette, so crossing folders would mean re-quantizing, not just reordering; not done by this drag). The reserved blank tile can never be dragged, or have anything dropped before it; it always stays first.
- Added: every tile/sprite row also shows its real export index as a "[N]" prefix, the exact same number `AssetExportIndexer` computes for export, category-wide (not per-folder), so what's shown can never drift from what gets exported. Recomputed for the whole category on any add/remove/replace, since one asset's index changing shifts every sibling that sorts after it.
- Fixed GridSplitter panes (main window, Map Editor, Metatile Editor) being draggable past the window's actual bounds: could silently store an oversized column width that only became visible on the next full layout pass (e.g. maximizing). All splitters now clamp live against the real current window size on every drag tick.
- Widened all GridSplitters to 5px (was 1px in Map Editor/Metatile Editor) so they're easier to grab.
- Added: Metatile Editor can now edit an existing metatile in place (click it in the library to load it into the draft, "Save Changes" writes back into the same metatile (every map already placing it picks it up immediately). Ctrl+click a draft cell to clear it back to unfilled while sketching (every cell still needs a real tile before it can be saved). "Cancel" button discards an in-progress edit.
- Fixed: after Save Changes or Delete in the Metatile Editor, the draft could silently stay loaded with stale data, so the next "Create Metatile" click would create an unwanted duplicate.
- Added: Atlas Slicer offers a "place the transparent tile first" checkbox when a slice contains a fully transparent cell and the target category doesn't already have one: moves it to export index 0 so it's easy to find (e.g. as a walk-through tile) instead of paging through the rest.
- Fixed: "place the transparent tile first" changed the underlying export order but the project tree didn't actually show it first: the tree's display order was plain insertion order, not SortIndex.
- Fixed: deleting a source image (which cascades to delete every tile/sprite it produced) never freed the now-unused 4bpp palette bank slot: it lingered forever (visible, "Optimize"-able, survives save/reload) even once its folder had zero real assets left. The equivalent cleanup already existed for flat/8bpp palettes but was missing for 4bpp banks in this one delete path.
- Added: a "Blank" reserved tile and metatile are now auto-generated (not detected/imported from any source image) the first time a Tile4Bpp/Tile8Bpp category, a given metatile Kind+GridSize, or a map of that GridSize is first used, always undeletable and always sorted first, so it's guaranteed to be export index 0. Replaces the map grid's old 0xFF "empty cell" sentinel entirely: an unpainted/erased cell now just references this real metatile, giving a branch-free blit a genuine blank pattern to read instead of an out-of-bounds index, and giving hardware tilemap code a real tile to draw when explicitly clearing a cell. - Fixed: opening the Metatile Editor on an empty Kind+GridSize didn't show its reserved blank metatile until the user created their first real one there: now it's ensured (and shown) as soon as that Kind+GridSize is selected, matching the same "always there" guarantee everywhere else.
