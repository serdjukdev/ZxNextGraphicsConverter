# Changelog

## Unreleased

- Fixed: shrinking a map with "Resize..." left every object that stood in the cut-away area sitting outside the new bounds. Such an object was invisible in the Map Editor and impossible to select or delete there (the canvas is exactly the map's size), yet it was still written into the exported `<map>_objects.asm`, with coordinates outside the level. Only objects pushed to a negative coordinate (off the left/top edge) used to be dropped; the right/bottom edge now drops them the same way, so the Resize dialog's "Will drop N sprite(s)" count is what actually happens. An object merely overhanging the new edge, with its top-left corner still inside, is kept, since that is a position you can place by hand too. A Link pointing at a dropped object is cleared, and one Undo restores the whole resize, dropped objects included.
- Fixed: the same off-map objects could also be created by Alt-dragging a selection past the map's edge (or Alt+Shift+dragging a copy there) and by pasting a group of objects near an edge or onto a smaller map. Those now drop, exactly like grid cells moved off the map always have, and the status line reports how many.
- Fixed: a project already damaged by the resize bug above is repaired when you open it: every object outside its map's bounds is removed (links pointing at one cleared) and the "Project opened with notes" dialog says how many. Without this the stale objects would have kept exporting until the next resize of that map.

- Added: Settings checkbox "Set ULA-over-tilemap bit (bit 0) on every exported Tilemap attribute byte" (off by default). Every 4bpp Tilemap tile's exported attribute byte (bits 7-4 palette, bit 3 Mirror X, bit 2 Mirror Y, bit 1 Rotate) has an unused bit 0 that real hardware (nextreg 0x6C) reads as a per-tile ULA-over-tilemap priority flag; off keeps writing 0 to every tile's bit 0 as before, on writes 1 to every tile's bit 0 instead, in both the GridSize=1 direct-cell export and every metatile cell. One project-wide export switch, not a per-tile editor control. The affected `_grid.asm`/`_metatiles.asm` header comments state which value was used.
- Added: a map's exported `<map>_objects.asm` now writes an address label, `<map>_objects_<type name>:`, right before the first object of each type in the file (objects are already grouped by type, see the per-type `_count` lines added earlier). A type with 0 objects placed on this particular map gets no block label, and untyped objects never get one either, since they aren't a real entry in "Manage Types...".
- Added: right-click now applies "Set Type" / "Set User Byte" to the WHOLE sprite selection at once, when one is active (Alt-drag a marquee first, then right-click anywhere on the canvas). Previously right-click only ever targeted whichever single object sat directly under the cursor, so tagging several objects the same type still meant clicking each one individually even with a selection made. The picked type/byte overwrites whatever each selected object already had, as one undo step; the "Link" menu item is hidden in this batch mode since linking is pairwise. The existing one-object-at-a-time "Set Type"/"Set User Byte" toolbar tools are unchanged for tagging objects that aren't selected.
- Added: a map's exported `<map>_objects.asm` now writes one `<map>_objects_<type name>_count: equ` constant per project-wide Object Type (from "Manage Types..."), in that list's order, right after the existing `<map>_objects_count`. A type that places 0 objects on this particular map still gets its own `_count: equ 0` line, so game code can always rely on every type's count constant existing regardless of which maps actually use it.
- Added: the Export dialog now shows a prominent red warning banner listing every placed object across every map that has no type assigned (e.g. "Level1: Enemy at (32, 64)"), so a forgotten "Set Type..." doesn't silently slip into an export. Non-blocking: Export stays enabled either way, an untyped object exports fine.
- Added: a "Show in Map Editor" flag for Sprite4Bpp/Sprite8Bpp sub-folder sprites, set per sprite from a checkbox next to the padlock or the right-click menu (tooltip explains it). Any number of sprites in one sub-folder can be flagged, for example several different enemies' idle frames sharing one 16KB pattern bank, each independently placeable on a map. Flagged sprites join root sprites in the Map Editor's sprite palette regardless of the broader "Allow sub-folder assets in map/metatile editor" setting; a placement's exported `spriteIndex` always resolves from that sprite's own local export index within its sub-folder, so toggling the flag later never changes already-exported map data. Purely a palette-curation flag, cosmetic only.
- Added: the Project Tree's status line now shows a Sprite4Bpp/Sprite8Bpp folder's bank usage (bytes used out of the 16KB shared sprite pattern memory pool) when that folder or an asset in it is selected.
- Added: object types in "Manage Types..." can now be reordered with Move Up/Down buttons. List order already set each type's export `equ` number in `object_types.asm`; it now also controls the init order of that type's objects within every map's exported `<map>_objects.asm`. Objects are grouped by their type's list position (untyped objects always last), with the relative order preserved within one type and among untyped objects. Useful when a type with many placed instances, e.g. a platform type, needs to initialize before other types on real hardware.
- Added: a "Templates" palette in the Map Editor, next to the existing Metatile palette (toggle between the two with the buttons above the list). Select a rectangle on a grid layer and click "Save as Template..." to name and store it: a reusable WxH block of graphics only, no map objects. Templates filter by Kind/GridSize exactly like the Metatile palette, so a Tilemap template never appears while the 8bpp layer is active and vice versa. Selecting a template arms a stamp tool: a translucent blue footprint follows the cursor over the canvas, and a click writes the whole block at that position in one undo step, silently clipped at the map's edges rather than refused. "Delete Template" removes the selected one (not undoable, same as deleting a map). Templates are stored project-wide and stay correct if a metatile they reference is later deleted or reordered elsewhere in the project.
- Added: in Atlas Slicer's "Slice into metatile blocks" mode, a block whose resolved tile composition (same tiles, same cell order) exactly matches a metatile already created earlier in the same slice now reuses that existing metatile instead of creating an identical duplicate. The default-selection/capacity preview (the "N metatiles will be made" count and the 255-per-Kind cap enforcement) accounts for this too, so a whole-block duplicate no longer costs a metatile slot there either.
- Added: the Source Images panel now accepts Ctrl+V to paste an image from the clipboard as a new source image (named `clipboard_<timestamp>`), alongside the existing Import/drag-and-drop. Reads the clipboard's "PNG" format, "Photoshop DIB Layer X", or CF_DIBV5 first (all of which can carry a real alpha channel), falling back to the plain bitmap otherwise. If no format in the clipboard actually carried transparency (a known limitation of some apps' copy, including some Photoshop versions, which paste an opaque 24bpp image with no alpha at all), a warning dialog says so and the image is pasted fully opaque; export/save it as a PNG file and import that instead if it needs transparency.
- Changed: a map's exported `_objects.asm` header comment now lists each of the 8 placement bytes on its own line (byte 0 spriteIndex, 1-2 X, 3-4 Y, 5 type, 6 connect, 7 userByte) instead of one dense paragraph.
- Added: hovering over a sprite in the Map Editor's sprite palette now shows a tooltip with the sprite name and how many objects of that type are currently placed on the active map (e.g. "Enemy (3 on map)"). The count updates after every placement, erase, paste, delete, copy, resize/trim, undo, and redo.
- Added: right-click "Lock all in folder" / "Unlock all in folder" on any category root or sub-folder, as a faster alternative to clicking each padlock one by one. Scope is always the folder's own direct assets (root-folder assets for a category root; the sub-folder's own assets otherwise). A status line confirms how many were changed.
- Added: Settings checkbox "Organise output into sub-folders matching the project tree" (off by default for compatibility). When on, the export directory gets a named sub-folder per asset category (e.g. `Sprite8Bpp/`, `Tile4Bpp/`) and a further sub-folder per user sub-folder inside it; shared category-wide `.asm`/`.pal` files go into the category root, per-subfolder binaries into their own sub-directory. Tilemap grid/metatile files go into `Tile4Bpp/`, 8bpp grid/metatile files into `Tile8Bpp/`. Objects and object types stay at the output root.
- Added: Settings checkbox "Allow sub-folder assets in map/metatile editor" (off by default). When on, Sprite4Bpp and Sprite8Bpp sub-folder sprites appear in the Map Editor sprite palette alongside root sprites, and Tile8Bpp sub-folder tiles appear in the Metatile Editor tile palette. Their export index is local to the sub-folder binary (matching the `s4_<subfolder>_<name>` / `t8_<subfolder>_<name>` label). Dragging a root sprite or Tile8Bpp tile that is currently placed on a map or used in a metatile into a sub-folder is also unblocked when this setting is on. Turning the setting off while sub-folder placements exist removes them and resets affected metatile cells to the blank tile, with a notification.
- Added: Sprite4Bpp sub-folder ASM exports now include a `s4_<subfolder>_pal_table:` label immediately before the first `_pal` byte in that sub-folder's section, so game code can look up a sprite's palette slot by its local index (`s4_walk_pal_table + localIndex`) the same way root exports support `s4_pal_table + spriteIndex`.
- Fixed: a newly created sub-folder appeared at the bottom of the tree instead of at its alphabetically sorted position among sibling sub-folders; it would only move to the right place after reloading the project.
- Fixed: deleting a Sprite4Bpp or Tile4Bpp sub-folder crashed with a "not a flat-folder-palette category" error, because folder deletion always tried to compact the flat per-folder palette even though those two categories share a 16-slot palette bank instead. The assets were actually removed under the hood, but the crash left the folder showing stale (now-empty) rows in the tree until the project was reloaded, and deleting sprites from those stale rows reported "0" to delete. Deleting a folder in any category now compacts whichever palette storage that category actually uses.

## v0.6.0 (2026-09-11)

- Added: you can now drag a tile/sprite row between folders of a shared-palette category (Sprite4Bpp / Sprite8Bpp / Tile8Bpp). Drop it on a row in another folder to move it there and position it before/after that row, or drop it straight onto a folder to move it to the end. Useful for slicing a spritesheet into the root and then sorting the frames into sub-folders. Because the palette is shared across the category there is no re-quantize. Moving a root asset that's currently placed on a map or used in a metatile into a sub-folder is refused (a sub-folder asset can't be referenced); moving into the root, or between sub-folders, always works. After such a move the tree keeps the moved row in view instead of scrolling to the top. Layer2 and Tile4Bpp reorder within one folder only, as before.
- Added: Sprite4Bpp now supports user sub-folders, the same way Sprite8Bpp does. Only root-folder sprites go on maps; a sub-folder is a self-contained "bank" (its own binary file, meant for animation frames or a swappable sprite set) that the game loads on its own. The whole category still shares one 16-slot palette bank and exports one address-map `.asm` and one `.pal`, with a separate `.spr` per folder. In the `.asm`, root sprites keep their `s4_<name>: equ <pattern> / s4_<name>_pal: db <slot>` form (with `s4_pal_table:` back as a single shared label before the run of `_pal` bytes), and each sub-folder sprite is `s4_<subfolder>_<name>` with the pattern number local to that sub-folder's binary. Because 16 slots is tight, importing a sprite that doesn't fit first repacks the whole bank automatically and retries; if it still doesn't fit you get the overflow dialog (cancel = the sprite isn't added).
- Fixed: the "palette is full" message on an 8bpp sprite/tile import still suggested moving the image to another sub-folder for a fresh palette, which stopped being true once those sub-folders started sharing one category palette. It now says to reduce colours or re-quantize the category; the "another sub-folder" advice is kept only for Layer2, whose sub-folders do still have their own palettes.
- Fixed: the Map Editor let you place a Sprite8Bpp/Sprite4Bpp sub-folder sprite on a map, but a sub-folder sprite is a separate "bank" the object system can't address, so its exported `spriteIndex` byte was meaningless and its presence also shifted every root sprite's `spriteIndex` away from its `s8_<name>` label. Sub-folder sprites no longer appear in the Sprite palette; the `spriteIndex` byte (and its 256 cap) now count only root-folder sprites; exporting a map that still places a sub-folder sprite fails with a clear message; and opening an older project drops any such placement with a note.
- Fixed: a Tile8Bpp metatile's `tileIndex` byte was ranked across the whole category, including user sub-folder tiles, even though sub-folder tiles are a separate "bank" that a metatile can never reference. Adding sub-folder tiles therefore shifted every root tile's exported `tileIndex` away from its own `t8_<name>` label. The `tileIndex` byte (and the 256-tile export cap that guards it) now count only the category's root-folder tiles, so a metatile cell's byte always matches the root tile's `t8_` label and its `[N]` in the tree. The tree's `[N]` is now a per-folder number too: a root asset shows its placement index, a sub-folder asset shows that sub-folder's own local export index.
- Fixed: `object_types.asm` wrote `obj_<name>` straight from the type name, so an object type with a space or a `.` in its name produced a label sjasmplus can't assemble. Type names now go through the same assembler-label sanitizer as every other exported name label, and are de-collided per file (`_2` / `_3`).
- Added: `.zxngc` project files now carry a format version. Opening a project saved by a newer build of the app still works but shows a one-time note that some newer data may not load. Opening an old project whose 8bpp sprite/tile sub-folders each had their own separate palette (the layout before sub-folders shared one) now merges those palettes into the single shared one on load, re-indexing the affected tiles/sprites so their colours are preserved, and notes that it did so; if the combined colours won't fit one palette it says to re-quantize instead.
- Changed: every button in the app now shares one flat, rounded style (subtle hover, a filled blue fill on a dialog's default/confirm button), so the Map Editor, Metatile Editor and every dialog (New Map, New Project, Object Types, Resize Map, Re-quantize, ...) look consistent. In the Map Editor the layer-order arrows and the palette-reset button became compact icon buttons, the map-list and tool buttons were regrouped into even rows, and the sprite-tool buttons now lay out two per row so Redo no longer disappears under the canvas splitter; an active tool is marked amber instead of a hard orange.
- Changed: the Project Tree, Source Images panel and Export dialog were restyled to one visual language. Tree folder rows are now rounded chips tinted by category type (green 4bpp, blue 8bpp, violet Layer2; a sub-folder is a lighter shade of its parent), category roots show a short label ("Sprite 4bpp", "Layer2 320x256") instead of their raw folder path, and long sub-folder/asset names are truncated with an ellipsis (full name on hover). The padlock and the Tile8Bpp priority arrow now sit in a fixed right-hand column so they line up down the list. Asset rows have a faint zebra stripe and a category-tinted selection highlight. The left pane no longer shrinks below the width its content needs. Source Images entries became hover/selection cards with the same look. The Export dialog's row grid gained a 4px category-tint bar per row, zebra striping, a soft selection highlight, cleaner headers, a rounded frame, and flat buttons (Export as a filled primary). No behaviour change: names, folder paths, and every command are unchanged.
- Added: every object on a map now gets its own address label in the exported `<map>_objects.asm`, one per placement, written straight onto that object's `db` line as `<map>_objects_<sprite name>_<x>_<y>:`. Game code can point at an object by name with no address arithmetic. The label is the sprite asset's name plus the placement's X and Y (so two placements of the same sprite still differ); a `_2` / `_3` suffix is added only when even the coordinates match. The whole-table `<map>_objects:` label and `<map>_objects_count` are unchanged. All names run through the same assembler-label sanitizer as the tile/sprite labels.
- Added: every metatile in an exported `<map>_<layer>_metatiles.asm` now carries its own address label on its record, `<map>_<layer>_metatiles_<metatile name>:`, so game code can reference a metatile by name. The label is additive: the grid file still references metatiles by their local dense index and the record order is unchanged. Names are sanitized and de-collided per file (`_2` / `_3`); the used-set is seeded with `count` and `size` so a metatile name can't shadow the `<rowKey>_count` / `<rowKey>_size` constants.
- Changed: the Tile4Bpp graphics-map `.asm` is now a compact name-labelled palette table (`t4_pal_table:` then `t4_<tile name>: db <4bpp palette index 0-15>`, one byte per tile in tile order) instead of the old per-tile bank/palette/offset record. 4bpp tiles upload as one contiguous blob, so there is no per-tile bank byte or byte-offset word any more; the tile number is just the byte's position in the table. Names go through the assembler-label sanitizer, matching the `s4_` sprite labels.
- Added: name-based labels in the exported graphics-map `.asm` for Sprite4Bpp (`s4_<name>`, plus `s4_<name>_pal` and the `s4_pal_table` run-start), Sprite8Bpp (`s8_<name>`) and Tile8Bpp (`t8_<name>`, with the sub-folder folded in as `t8_<subfolder>_<name>`), replacing the previous raw asset names. The index is local to that one export file. Names are sanitized and de-collided per file.
- Changed: Sprite8Bpp and Tile8Bpp sub-folders now share one palette with their category root (their sub-folders are colour "banks" of the same content, not independent images), and the Export dialog collapses such a category to a single row with one shared `.pal` file. One binary file per sub-folder is still written.
- Changed: Tile8Bpp tiles that live in a user sub-folder are no longer offered to the Metatile Editor or Atlas Slicer's metatile-block slicing (their export index is per-file local and would not match a metatile cell's project-wide tile index). Metatile tiles come from the Tile8Bpp root folder only.
- Added: a "Default pixel order for a new export row" setting (Row-major / Column-major), used as the starting choice for software 8bpp Tile rows in the Export dialog instead of always row-major. Still changeable per row there.
- Fixed: in the Metatile Editor, the first click right after selecting a metatile or tile in a list (on the scrollbar, or another item) could be swallowed and trigger a stray drag of the previously-clicked item, the same bug already fixed for the Project Tree. A drag armed by a click is now cleared on release and by any click that doesn't land on a draggable item.
- Added: pressing Enter in the Metatile Editor's name field now commits the metatile (Create, or Save Changes when editing an existing one), so a rename no longer needs a trip to the button.
- Added: a Layer2 "priority" toggle for Tile8Bpp tiles (a green up-arrow on the row, or Priority / No priority in the right-click menu, both working on a multi-selection). Turning it on gives every non-transparent colour the tile uses a second copy in its folder palette with bit 7 of the exported entry set, the Next hardware flag that makes a Layer2 colour draw on top of every other layer regardless of the normal order. Priority and normal tiles share one folder palette; a full palette offers a one-click optimize and retry. Transparent pixels are never made priority. The flag is saved with the project and survives re-quantize. In the palette strip a priority colour shows a small green corner marker, and that strip's swatches are now larger. Priority tiles (and metatiles that contain one) are marked with a green corner in the Metatile and Map Editor thumbnails, and the Map Editor preview draws priority tiles on top of every layer and sprite to match hardware. That last part is a preview aid only: the exported map is unchanged (one grid layer, one palette).
- Fixed: re-quantizing a whole folder or a multi-selection did not carry over the locked flag (single-tile Ctrl+R already did), so a locked tile could silently unlock.
- Added: a per tile/sprite lock in the Project Tree. Every row now shows a padlock (open means deletable, closed amber means locked); click it to toggle that one, or use the right-click Lock / Unlock item for a whole multi-selection. A locked asset cannot be deleted by anything: the Delete key, deleting its folder or source image, the new "Delete unused", or the Metatile Editor's 1x1 delete are all refused. It is meant to protect assets your game code references directly (animation frames, procedurally drawn tiles) that no map places. Locking does not affect reorder or export, the lock state is saved with the project, and re-quantizing a locked asset keeps it locked.
- Added: "Delete unused..." on a folder's right-click menu (a category root, for the whole category, or a sub-folder, for just that folder; not on Layer2). Deletes every tile/sprite in scope that no map places, directly or via any metatile, skipping locked ones, after showing the full list. The confirmation is explicit that "not used in this project" is not "not used in your build" (code-referenced frames, procedural tiles) and that deleting renumbers the export index of every remaining asset in the category. Not undoable.
- Fixed: in the Project Tree, the first click right after selecting a row was swallowed (and could trigger a stray drag-reorder of the just-selected asset): clicking the scrollbar or, now, a row's padlock immediately after a selection did nothing until a second click. A potential drag armed by the previous click was never being cleared on release or by a click that landed off a draggable row. — nothing stopped you from importing/slicing images into it, only to hit a silent 2x2 default the moment you created your first metatile, or a dead-end "close and reopen" message the moment you tried New Map (there was nothing to reopen: the project had never been saved). The app now forces New/Open Project up front whenever there's no recent project, looping until one exists.

## v0.5.0 (2026-08-31)

- Added: a live cursor-position status line under the Map Editor's canvas, showing the raw map pixel X/Y plus the tile cell (col,row, in the 8x8 tile grid) as you move the mouse. On a 2x2/4x4 project it also shows the metatile cell (col,row); on a 1x1 project there's no separate metatile concept, so only the tile position is shown. Updates live on mouse move and clears when the cursor leaves the canvas.
- Added: the Map Editor now reopens on whichever map you last had selected, instead of always starting with no map selected.
- Added: each map in the Map Editor now remembers its own view (scroll position, zoom) and active layer as you leave it (switching to another map, or closing the window), and restores it the next time that particular map is reopened.
- Added: the Metatile Editor's tile palette can now be dragged straight onto a draft cell to paint it, alongside the existing click-a-tile-then-click-a-cell flow (both work interchangeably; Ctrl+click still clears a cell).
- Added: Redo (Ctrl+Y) in the Map Editor, alongside the existing Undo (Ctrl+Z) — a new edit after an Undo clears whatever Redo history existed, same as every other editor.
- Fixed: a full map re-render (Undo/Redo, the map-list thumbnail, opening a map) was noticeably slow on large maps — it rebuilt one full-size bitmap per layer and wrote pixels one map cell at a time instead of batching the whole map into a single write. Now uses the same batched-write path already used for fast incremental repaint while painting.
- Added: Ctrl+C/Ctrl+V in the Map Editor — copies the current grid-cell or sprite selection and pastes it under the cursor, snapped to the tile grid, selecting the pasted result immediately so it can be Alt-dragged into place. Works across maps (copy on one map, switch to another, paste) with no remapping needed, since metatiles/tiles/sprites are shared project-wide; a pasted sprite's link, if any, is not carried over, same as a same-map copy.
- Added: the Map Editor's "Delete selected" button (for a map) now asks for confirmation first, instead of deleting immediately.
- Fixed: on a 1x1 ("no metatile") project, deleting a metatile in the Metatile Editor only removed the metatile wrapper, leaving its one underlying tile behind with no way to place it on a map again while still using up palette/bank space. Deleting a metatile now deletes the underlying tile too on a 1x1 project (same cascade already used when deleting a tile from the Project Tree), correctly updating the tree and freeing palette space.
- Added: a "Delete Unused" button in the Metatile Editor, next to "Delete selected" — deletes every metatile of the current Kind that no map places, with one confirmation for the whole group. Works the same way on a 1x1 project (deletes the underlying tile, same as the single-delete fix above).
- Added: multi-select (Ctrl+click / Shift+click, same as the Project Tree) in the Metatile Editor's "Existing metatiles" list — "Delete selected" now deletes every selected metatile with one confirmation for the group.
- Fixed: deleting a tile/sprite/folder/source image/metatile with a long cascade description (e.g. hundreds of affected tiles) could make the confirmation dialog grow past the screen with no way to scroll and read the rest. These confirmations now use a fixed-size, scrollable dialog instead.
- Fixed: bulk-deleting metatiles (multi-select or "Delete Unused") showed a generic "Delete N metatile(s)?" with no detail, unlike deleting one at a time — it now shows the same per-map cell-count breakdown as a single delete, aggregated across the whole batch.
- Added: selecting a tile or sprite in the Project Tree now shows a read-only usage summary (e.g. "Used in 3 metatile(s), 2 map(s)." or "Not placed on any map.") under its name in the Image Viewer panel. Informational only — never used to gate a delete, since a tile/sprite can be referenced by game code (e.g. animation frames) with no way for the app to know.
- Fixed: the Metatile Editor's tile palette and "existing metatiles" gallery, and the Map Editor's own metatile/sprite palettes, re-decoded every thumbnail's raw pixels from scratch on every refresh (after every Create/Update/Delete/reorder, or every map/layer switch) — most noticeable on a 1x1 project's gallery, which can hold hundreds of tiles. These now reuse a per-session render cache instead.

## v0.4.0 (2026-08-27)

- Added: a Settings screen (File → Settings...). General tab: export filename postfixes (the previously-promised configurable ones: graphics data, tilemap/8bpp grid and metatiles, objects), default dither mode for new imports, default export chunk size for a new row, New Map's default starting size, New Project's default metatile size, and the Map Editor's grid overlay colours/opacity. Shortcuts tab: every keyboard shortcut and mouse gesture in the app (including drag-to-reorder in the Project Tree and the Metatile Editor), grouped by area, with a tooltip per row for the full explanation. Real keyboard shortcuts (Ctrl+S, Ctrl+Z, Delete, Ctrl+R) now come from one shared registry that both the actual key bindings and this list read from, so the two can't drift apart.
- Fixed: the F1 (Help) shortcut only worked while focus happened to be in the Project Tree or Source Images panel: clicking into the Pixel Editor, Image Viewer, or Palette Strip first meant F1 stopped responding until you clicked back into one of those two panels. F1 is now intercepted at the Windows-message level for the whole main window, independent of which control currently holds keyboard focus.

- Changed: the project's metatile grid size (1x1/2x2/4x4) is now chosen once, up front, in the New Project dialog instead of lazily the first time it's actually needed (opening the Metatile Editor, checking Atlas Slicer's "slice into metatile blocks", or creating the first map). A project saved before this existed still resolves it once, right after it finishes loading, if it doesn't already have one locked.
- Removed: 3x3 metatiles. Nothing on this platform actually needs a non-power-of-two metatile size (no hardware requirement forces it), 2x2/4x4 keep the arithmetic and typical sprite-size alignment cleaner, and 3x3 turned out to be broken (silently created 2x2 metatiles instead) and unused in practice, so it's gone rather than fixed.
- Added: a 1x1 "no metatile" project mode: every Tile4Bpp/Tile8Bpp tile automatically gets its own single-cell metatile the moment it's imported (any import path: single drop or Atlas Slicer plain slice), so a GridSize=1 map's palette shows one paintable entry per tile with no metatile-authoring step at all; Atlas Slicer's "slice into metatile blocks" checkbox is hidden in this mode since a 1x1 block is identical to a plain tile slice. Export skips the metatile-table indirection entirely for these maps: each grid cell holds its tile's own index (+ attribute byte for the Tilemap layer) directly, and no `_metatiles.asm` file is produced.
- Fixed: a GridSize=1 map's cell-count limit was still the plain 16384 (1 byte/cell) figure, but its Tilemap layer actually exports 2 bytes/cell: a map that validated fine (e.g. 128x128) could silently produce an oversized export. The limit is now halved (8192 cells) for GridSize=1 specifically, enforced everywhere size is checked (New Map, Resize, map creation, export).
- Added: mirror/rotate/palette-slot editing for a GridSize=1 map's Tilemap layer, previously fixed at default orientation. A "Paint with" panel next to the palette lets you dial in the orientation/palette slot before painting or Fill Selection; right-clicking an already-placed cell opens a small dialog to change just that one cell's attributes in place (a no-op on an untouched/erased cell: its reserved Blank tile isn't a real tile to edit). The attribute is stored per map cell, entirely independent of which metatile (i.e. which tile) occupies it: editing a cell's attribute never changes its tile and never creates a new metatile, so it can never eat into the 255-per-Kind metatile cap no matter how many different orientations get used across a map.
- Fixed: the Recent Projects list (menu and startup auto-reopen) kept listing project files after they'd been deleted, moved, or renamed outside the app. Loading the list now drops any path that no longer exists and saves the cleaned-up list back, so a dead entry is gone for good the next time it's noticed.
- Fixed: the Rotate checkbox's preview (Metatile Editor, Map Editor's "Paint with" panel and cell-attribute popup) didn't match what real hardware actually draws. Rotate alone was previewed as a plain diagonal transpose; on real hardware (and confirmed against the tilemap.vhd RTL source) the Rotate bit is XORed into the Mirror X decision, so Rotate alone is actually a genuine 90-degree rotation, and Rotate+Mirror X together is what looks like a plain transpose. The exported attribute byte itself was always correct (it just carries the 3 bits as chosen); only the app's own preview pixels were wrong. Fixed to compute the exact same transform real hardware does.
- Added: the right-click cell-attribute popup (GridSize=1 Tilemap layer) now automatically targets the whole grid selection when one is active, instead of just the clicked cell: applies Mirror X/Mirror Y/Rotate to every selected tile as soon as you click OK, no extra opt-in step. A checkbox starts on a dash (WPF's native indeterminate state) when the selected tiles don't already agree on that setting; leaving a dashed checkbox alone keeps each tile's own value, only a checkbox you actually click gets applied uniformly to the whole selection. The preview image always shows just the clicked tile as a reference. Palette slot override is unaffected either way: it always applies to just the one clicked tile.
